05Vibe Coding

说清楚要什么，
剩下的交给代码

Vibe coding 不是「一句话生成一个 App」。它更像和一个手速极快的搭档合作： 我负责判断、审美和拆解，它负责打字。真正的功夫在于把模糊的「我想要那个感觉」， 翻译成它能执行、我能验收的具体描述。

AI 结对 小步迭代 可回滚 看得懂才算完

01 / Loop

我的五步循环

每一步都很短，短到可以在一次对话里走完一轮。

  1. 01

    先想清楚「完成」长什么样

    在写提示词之前，先用一句话说清验收标准：点哪个按钮、看到什么、在手机上会不会错位。想不清就别开始。

    验收标准用户路径
  2. 02

    写规格，而不是写愿望

    告诉它约束：技术栈、已有组件、颜色变量、不要动哪些文件。约束越清楚，返工越少。

    上下文约束边界
  3. 03

    先跑通最小版本

    能用 > 好看 > 好维护。第一版只求在浏览器里出现，再逐步加动效和细节。

    MVP迭代
  4. 04

    回读代码，自己验收

    逐段看懂它写了什么，跑一遍边界情况：窄屏、无 JS、深色模式、键盘操作。看不懂的部分，要求它解释。

    Review边界测试
  5. 05

    提交，留下可回滚的点

    每完成一个可用的阶段就提交一次。有 commit 才有退路，也才有「这次改动到底改了什么」的答案。

    Git小步提交

02 / Split

谁负责什么

把「理解」留在自己这边，是把 AI 用久的关键。

我负责

决定做什么、不做什么；判断视觉与交互是否对味；拆解任务、限定范围； 最后逐行验收，并对上线结果负责。

决策 / 审美 / 验收

AI 负责

写样板代码、查 API 用法、批量重命名与重构、生成测试数据、解释报错； 把重复劳动压缩到几秒。

实现 / 检索 / 重写

03 / Template

我常用的提示词结构

四段式：背景、目标、约束、验收。可直接复制改成自己的。

prompt.md · 新增一个页面 
# 背景
纯静态多页面站点，共享 /static/style.css 与 /static/script.js。
不引入框架、不加构建步骤。

# 目标
新增「学习笔记」页面，视觉与 ae.html 保持一致，
包含：页头、5 个步骤卡片、1 个代码块、底部上一页 / 下一页导航。

# 约束
- 复用现有 class：.page / .pageHero / .steps / .codeBlock / .nextNav
- 颜色只用 CSS 变量，不写死色值
- 深浅色主题、375px 窄屏都要正常
- 导航与页脚复制现有页面的结构，不要重写样式

# 验收
- 断网直接打开 HTML 仍可阅读
- 控制台无报错，无横向滚动
- 键盘 Tab 能走完所有可交互元素

05 / Principles

几条不变的原则

01 · 不要外包理解

代码能跑不等于我会了。看不懂就让 AI 解释，解释完再自己复述一遍。

02 · 小步、可验证

一次只改一件事，改完立刻看结果。大重构听着爽，出问题最难查。

03 · 先删后加

缺功能时加代码，出问题时先想能不能删。很多 bug 来自多余的兜底逻辑。

04 · 审美不可外包

AI 能给出十个版本，但选哪个、为什么选，只能自己判断。这也是我还在练画的原因。

这个站就是例子：多页面结构、主题切换、滚动进度和卡片动效，全是在对话里一轮轮改出来的。
